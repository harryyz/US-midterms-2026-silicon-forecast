# Synthetic Voters Give Republicans a 72% Chance of Keeping the Senate in 2026

## Overview

This repository forecasts all 35 U.S. Senate races of 3 November 2026 with silicon sampling. We turned 5,173 real respondents to the 2024 Cooperative Election Study (CES) into first-person personas and asked large language models, through OpenRouter, how each persona would vote. **Every vote choice in the forecast is synthetic: the people are real survey respondents, but their 2026 votes were generated by language models.** The answers are weighted to likely midterm voters, corrected with a 2024 backtest, and run through 10,000 simulated elections. Republicans keep control in 72% of simulations (median 52 seats, 80% interval 47 to 57). A state-level regression, built separately, is shown on the site as a second opinion.

Website: <https://harryyz.github.io/US-midterms-2026-silicon-forecast/>

## How the forecast works

1. **Personas** (`scripts/02-build_personas.py`). Up to 150 CES 2024 respondents per state, drawn with seed 853, each written as a first-person backstory: age, race, gender, state, education, family income, party identification, ideology, religious attendance and interest in politics.
2. **Queries** (`scripts/03-query_models.py`). Each persona is asked, five times at temperature 1, how they will vote in their state's race. Candidates are described by party only. Pure independents also get a forced-choice follow-up between the Republican and the main opponent. Every reply is saved with its model, timestamp, tokens and cost.
3. **Forecast** (`scripts/04-forecast.py`).
   - Each persona's Republican share is weighted by CES survey weight times midterm turnout, estimated from validated 2022 turnout.
   - Each model's state estimates are corrected with a line fitted to the 2024 backtest.
   - 10,000 elections are simulated with a shared national error (assumed, 3 points), a state error (measured, 4.7 points), model choice and sampling error.
   - The draws are saved as parquet.

Only GPT-4o mini and Llama 3.3 70B feed the forecast, because their training data ends before the 2024 election and they can be backtested. DeepSeek V4 Flash is shown for comparison only.

All model calls cost US$4.43 in total (169,280 replies).

## File structure

| Folder | Contents |
|---|---|
| `data/00-simulated_data` | Simulated respondents, LLM responses, post-stratification frame and forecast, used to build and test the pipeline before real data existed |
| `data/01-raw_data` | Raw data as downloaded, never edited by hand (see below for the one file not committed) |
| `data/02-analysis_data` | Personas, every model reply, the backtest, the forecast draws and the regression outputs, all as parquet |
| `scripts` | Numbered in run order (see below) |
| `tests` | Pytest suites, with pandera schemas, for the simulated data, real data, API responses, forecast, regression and website figures |
| `paper` | Quarto source for the website (`index.qmd`), bibliography, style sheet and fonts. `_regression.qmd` is the full write-up of the regression, kept in the repo but not included on the page |
| `docs` | The rendered website, served by GitHub Pages |
| `other/sketches` | Hand-drawn sketches of the page layout, figures and tables |
| `other/llm_usage` | Working notes kept during development |

### Scripts

| Script | What it does |
|---|---|
| `00-simulate_data.py` | Simulates respondents, personas, LLM responses, the frame and a forecast |
| `00b-simulate_regression_inputs.py` | Simulates the regression's inputs |
| `01-download_data.py` | Downloads the cumulative CES from Harvard Dataverse and saves the 2012 to 2024 respondents we use |
| `01b-download_acs.py` | State demographics from the Census Bureau ACS 5-year estimates (needs a free Census API key) |
| `01c-download_results.py` | Certified statewide Senate returns, 1976 to 2024 (MIT Election Data and Science Lab, via Dataverse) |
| `01d-download_president.py` | Certified statewide presidential returns, 1976 to 2024 (same source) |
| `01e-download_candidates.py` | 2026 nominees from Wikipedia and official portraits from the Congressional Bioguide |
| `02-build_personas.py` | Builds the 2024 (backtest) and 2026 (forecast) persona sets |
| `03-query_models.py` | Queries the models through OpenRouter |
| `04-forecast.py` | Backtest, calibration and the 10,000-election simulation |
| `05-regression.py` | The regression forecast |
| `06-make_figures.py`, `07-race_views.py` | Figures, race cards and map for the regression write-up |
| `08-silicon_views.py` | Every figure and table on the website, built only from stored results |

`data/01-raw_data/senate_races.csv` (2024 and 2026 ballots) and `senate_results_2024.csv` (2024 results) were entered by hand from Wikipedia and checked race by race; each row records its source URL.

## How to reproduce

Requires [uv](https://docs.astral.sh/uv/) and Python 3.13. Quarto is installed by uv.

```bash
uv sync                          # recreate the environment from uv.lock
cp .env.example .env             # then add OPENROUTER_API_KEY (and CENSUS_API_KEY for 01b)
```

**Rebuild the forecast and website from the stored model replies (no API calls, no cost).** The replies are committed, so the forecast is exactly reproducible (seed 853):

```bash
uv run scripts/04-forecast.py
uv run pytest
uv run quarto render paper       # writes the site to docs/
```

**Rerun everything from scratch.** This makes about 170,000 paid API calls (about US$4.50). Because answers are sampled at temperature 1, a rerun will give slightly different replies.

```bash
uv run scripts/00-simulate_data.py
uv run scripts/01-download_data.py           # and 01b to 01e
uv run scripts/02-build_personas.py

# 2024 backtest
uv run scripts/03-query_models.py --personas data/02-analysis_data/personas_2024.parquet --year 2024
uv run scripts/03-query_models.py --personas data/02-analysis_data/personas_2024.parquet --year 2024 \
  --forced-choice --only-pid7 Independent

# 2026 forecast
MODELS="openai/gpt-4o-mini meta-llama/llama-3.3-70b-instruct deepseek/deepseek-v4-flash"
uv run scripts/03-query_models.py --personas data/02-analysis_data/personas_2026.parquet --year 2026 \
  --models $MODELS
uv run scripts/03-query_models.py --personas data/02-analysis_data/personas_2026.parquet --year 2026 \
  --models deepseek/deepseek-v4-flash --no-reasoning --run-name 2026_deepseek --concurrency 20
uv run scripts/03-query_models.py --personas data/02-analysis_data/personas_2026.parquet --year 2026 \
  --models $MODELS --forced-choice --only-pid7 Independent --concurrency 20

uv run scripts/04-forecast.py
uv run scripts/05-regression.py
uv run pytest
uv run quarto render paper
```

Add `--dry-run --limit 3` to any query command to print the prompts without calling a model. Query runs save in batches and skip personas already done, so an interrupted run can be restarted with the same command.

The site is deployed by `.github/workflows/deploy-pages.yml`, which publishes `docs/` whenever it changes on `main`.

## Data not included

The cumulative CES file (`data/01-raw_data/cumulative_2006-2025.feather`, 138 MB) is over GitHub's 100 MB file limit and is not committed.

- **To get it:** run `uv run scripts/01-download_data.py`, which downloads it from Harvard Dataverse (`doi:10.7910/DVN/II2DB6`, no account needed). Alternatively, download the feather file from that page by hand.
- **Where it goes:** `data/01-raw_data/`.

The script then writes the extracts the rest of the pipeline uses, which are committed: `ces_2022_2024.parquet` and `ces_2012_2020.parquet`. A small sample, `ces_2022_2024_sample.parquet`, with the same columns, is also committed for testing.

The intermediate query batches (`data/02-analysis_data/parts_*`) are also ignored. They are combined into the committed `responses_*.parquet` files.
